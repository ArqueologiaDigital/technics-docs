# Technics SX-KN7000

The **Technics SX-KN7000** (2002) is the successor to the [KN5000]({{ site.baseurl }}/system-overview/).
This section documents what has been established so far, mostly from its
system-update disks and from emulating them.

> **Status:** the update-disk container format is fully decoded. Four program
> builds (942, 941, 935 and the upper half of 929) and two table builds (84, 83)
> have been extracted from update disks, and all of them verify against
> Panasonic's own checksums except the SP7001 set (942/83), whose shipped
> checksums predate its final payload; its two table disks match the dumped
> table byte for byte. The byte-exact disassembly names 2,302 functions and
> converts 504 of them, plus 437 library functions, to real MN10300 source. It also
> rebuilds the SP7001 firmware and its plug-in program `BASEEXT.XAP`, and shows how
> the SP7001's plug-in is installed and run
> ([SP7001 Firmware]({{ site.baseurl }}/kn7000-sp7001-firmware/)). The KN7000 driver has been in mainline
> MAME since [#16250](https://github.com/mamedev/mame/pull/16250) (2026-10-07).
> It emulates the LCD, control panel, floppy, SD and MIDI, but it makes no
> sound: the tone generators' registers are decoded but produce no output, and
> the ADSP-21065L effects DSP is not emulated. The project's own overlay build
> plays the voices from the wave ROMs read on the owner's instrument in
> October 2026, through the emulated effects DSP
> ([Sound Subsystem]({{ site.baseurl }}/kn7000-sound-subsystem/)). Much
> of the KN5000's knowledge does **not** carry over directly because
> the KN7000 uses a completely different CPU — but the two firmwares share a
> common source lineage (see [Shared Codebase Map]({{ site.baseurl }}/technics-shared-codebase/)).

## The main CPU is a Panasonic MN10300 — not a TLCS-900

The single most important finding for anyone extending KN5000 knowledge to the
KN7000: **the CPU architecture changed.** The KN7000 program image disassembles
cleanly with `unidasm -arch mn10300` and embeds the kernel/library banner
`MILK MN10300 Ver1.0R1` at file offset `0x3B8AAC`. It also links **zlib 1.0.4**
(deflate/inflate banners at `0x3B8604` / `0x3B863C`).

The practical consequence: **none of the KN5000's TLCS-900 opcode-level
knowledge transfers** — instruction encodings, patch offsets, and the
disassembler backend are all different. What *does* carry over is the update
container format, the higher-level firmware design, and large amounts of shared
resource data (see the [Shared Codebase Map]({{ site.baseurl }}/technics-shared-codebase/)).

## CPU clock: 64 MHz, with caches (measured)

The main CPU is **IC4 = MN103002A** on the MAIN 1/5 board. Its clock is now measured.
On 2026-10-20 a timing probe ran on the owner's instrument (program 893): pass 9 of the
[ROM dumper]({{ site.baseurl }}/kn7000-rom-dumper/#the-probe-builds-passes-5-to-9). It timed
119 instruction and memory tests against the CPU's timer 4, whose rate pass 8 had confirmed.
A register `add` takes 15.6 ns, one cycle at **64.02 MHz**: the 16 MHz crystal at X1 multiplied
by 4 (the part's "4-fold" mode).

**The earlier 32 MHz was wrong**, though both of its inputs hold. X1's part code `H0J160500026`
reads as 16.0 MHz (SCHEMATIC DIAGRAM-1; compare X103 `H0J240` = 24 MHz). The firmware's MIDI
set-up fixes the peripheral clock: MIDI is 31,250 baud, the serial channel's baud clock is Timer
3's underflow ÷ 8, and Timer 3 reloads at `TM3BR = 0x3F`, so

> baud = IOCLK / (8 × (TM3BR + 1)) → 31250 = IOCLK / 512 → **IOCLK = 16.000 MHz**, exactly.

The mistake was the step from there to the core: it assumed a ×2 multiplier and an IOCLK of half
the core clock. The multiplier is ×4 and IOCLK is a quarter of the core clock. The merged MAME
driver and the blog post *"Learning to tell time"* still give 32 MHz. (The KN6000 and KN6500
manuals print a 32 MHz X1; their core clocks are unmeasured.)

**Caches.** The firmware turns both caches on at boot (CHCTR, `0x20000070`: `0x30`, then `3`, and
later bit 7), and pass 9 read CHCTR as `0x8F` on the unit. The firmware's own purge routine shows a
4 KB, two-way data cache with 16-byte lines. The MN103002A's datasheet abstracts give a 4 KB
two-way instruction cache too. Work RAM, the program and table flash, and the library RAM are
reached through the cache at `0x4xxxxxxx`/`0x5xxxxxxx`; the same memory is uncached at
`+0x40000000`.

**What an access costs on the unit** (pass 9, clean runs, the instruction's own cycle included):

| access                                                     | ns            | cycles      |
|------------------------------------------------------------|---------------|-------------|
| register `add`; any load or store that hits the cache      | 15.6          | 1           |
| work RAM, uncached 32-bit load (`0x90000000` view)         | 96.6          | 6.2         |
| work RAM, cached load that fills a new 16-byte line        | 389.3         | 24.9        |
| program flash / library RAM, line fill                     | 513.0 / 294.8 | 32.8 / 18.9 |
| IC23 (backup SRAM) or IC21 (custom flash), uncached 16-bit | 141.5         | 9.1         |
| on-chip timer or interrupt register                        | 124.7         | 8.0         |
| the board strap at `0x98070000`, 16-bit load               | 562.8         | 36.0        |
| LCD frame (`0x9CE00000`), 16-bit load                      | 693.6         | 44.4        |
| LCD frame, 16-bit / 32-bit store                           | 439.3 / 888.5 | 28.1 / 56.9 |

The LCD figures vary: some LCD tests' median runs took 2 to 2.4 times their clean ones, and
Another World's own benchmark measured 1.3-1.8 µs per 16-bit LCD store while the display was
active, three to four times the clean figure
([Display Subsystem]({{ site.baseurl }}/kn7000-display-subsystem/#what-the-lcd-costs-the-cpu)).
The bus controller registers read back as the firmware set them for a class-1 board: MEMCTR0-7 =
`0x8904`, `0x0804`, `0x0824`, `0x0424`, `0x0865`, `0x0004`, `0`, `2`. Which chip select serves
which window, and what each MEMCTR field means, is not documented anywhere we have.

The project's overlay emulator now runs the core at 64 MHz with these costs, a fetch queue and
both caches; against pass 9 it lands 99 of 109 reliable tests within 3 %
([MAME Emulation Gaps]({{ site.baseurl }}/mame-emulation-gaps/#kn7000-the-overlay-emulator)).
Mainline MAME charges one cycle per instruction at 32 MHz and nothing for memory.

The program-flash mapping (`file offset + 0x48400000`) is proven by ~68,000
self-consistent 32-bit pointers in the image.

## Hardware map (from service-test strings)

The firmware's service test mode enumerates the hardware with IC designators:

- Program ROM **IC16 / IC17**, rhythm ROM **IC18 / IC20**, custom flash **IC21**,
  picture ROM **IC19**
- Work RAM **IC12 / IC13**, static RAM IC23, LCD V-RAM IC104 (the parts list names IC104 the LCD controller), fast S-RAM IC14/IC15
- **Dual tone generators**: main TG ROMs **IC203 / IC204**, sub TG ROMs **IC207 / IC208**
- DSP **IC306**, DSP RAM **IC307 / IC308**, floppy controller **IC103**
- Panel groups **CPL / CPC / CPR / CPSD** (only CPL and CPR carry a microcontroller, an M37471M2196S each; see [Control Panel Protocol]({{ site.baseurl }}/kn7000-control-panel/))
- Wave expansion board, SD card slot, video-out

## I/O register map (from firmware analysis)

Static analysis of every absolute I/O access in the program ROM recovered
**112 memory-mapped I/O registers**, in these banks:

| Bank                        | Registers | Likely function                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
|-----------------------------|-----------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `0x20000000`                | 7         | small register block; the reset code writes `0x30`/`0x03` to `0x20000070`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `0x32000000`                | 15        | system / timers (`0x40`/`0x42` loaded with `0x497`/`0xEA6` at reset; `0x800`–`0x80F` is the on-chip DMA controller's channel 0)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `0x34000000`                | 58        | the MN103002A's **on-chip peripherals**: interrupt controller (`0x34000100`–`0x340002FF`), the three serial channels (`0x34000800`–`0x3400082F`: control-panel link and two MIDI ports) and the timers (`0x34001080` onward)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `0x36008000`                | 8         | **bit-mapped control / GPIO** — every access is `bset`/`bclr`/`btst`; `0x36008004` is toggled 125× (chip selects / strobes / resets)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `0x98040000` + `0x98050000` | 7 + 9     | **parallel 16-bit register sets — the dual tone generators** (IC201 and IC205; their wave ROMs are IC203/204 and IC207/208)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `0x98020000`                | 8         | **floppy disk controller IC103** (custom C1DB00000607, N82077AA-compatible). Confirmed by the service-manual schematic — a 3-to-8 chip-select decoder (IC1, TC74VHC138F) splits the `0x98000000` region by CPU A16–A18; output **Y2 = FDC.CS = 0x98020000** (Y4 = `0x98040000` = the TG select fixes the base). The firmware drives the standard PC/AT register file here: `+4` DOR, `+8` MSR/DSR, `+A` data FIFO, `+E` DIR/CCR. Data moves by DMA: the controller's DRQ drives the MN103002A's on-chip DMA channel 0 (`0x32000800`), which transfers each byte through the **FDC.DACK slot at `0x98010000`** (decoder output Y1), and its INTRQ is wired to IRQ2 (INTC group `0x19`). *(This bank was previously mislabelled "sound-subsystem control"; it is not sound.)* |
| `0x98060000` / `0x98070000` | —         | further sound-subsystem control (`0x98060000`) + a board strap word (`0x98070000`), which reads `0xF8F7` on the owner's unit (pass 9): board class 1, hardware subtype 2, both tone generators present                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

The reset code's first act is programming the `0x36008000` GPIO and the
`0x32000000` timers, then toggling `0x36008004` — the classic hardware bring-up
sequence. Upstream MAME's driver (`src/mame/matsushita/kn7000.cpp`, since
#16250) models the known banks with real devices (the on-chip serial,
interrupt, timer and DMA blocks inside the MN10300 core, the FDC, the SD
interface and the tone-generator ports) and logs the rest.

## Tools & repositories

The extraction and disassembly tooling lives in dedicated repositories:

- **kn7000_extraction** — decompresses the `.SLD` update files and rebuilds the
  flash images (verified against the disks' own checksums); also splits the table
  image into its 84 asset segments.
- **[`technics-roms-disasm`](https://github.com/ArqueologiaDigital/technics-roms-disasm/tree/main/kn7000), `kn7000/`** (until 2026-10-19 the separate `kn7000_disassembly`) — a
  byte-exact reassembly project for the MN10300
  firmware. `make verify` reassembles the source and asserts a 100% byte-match
  against the originals.

## Source of these disks

The KN7000 system-update disks documented here were distributed via
[ca-software.com](http://www.ca-software.com/technics/downloads/index.htm) and
kn7000.de (now preserved only in the Wayback Machine):

- **kn7-16** — v1.6 program update, build 941 (2 floppies: `JK1.SLD` + `JK2.SLD`)
- **kn7-15** — v1.5 program update, build 935 (2 floppies, `kn7-15a` / `kn7-15b`)
- **kn7-14** — the v1.4 update, on four floppies: disks 1–2 hold the program
  (build 929) and disks 3–4 the table (build 84, `JKT1.SLD` + `JKT2.SLD`). Disk 1
  survives only as an archived 'page not found' stub, so the lower half of the
  v1.4 program is unpreserved.
- Key Soft Service's **SP7001 PLUG-iN** update: program build 942 and table
  build 83, on four self-extracting ZIP disks; the second table disk also carries
  `BASEEXT.XAP` (see [SD PLUG-iN]({{ site.baseurl }}/kn7000-sd-plugin/) and
  [SP7001 Firmware]({{ site.baseurl }}/kn7000-sp7001-firmware/)).

(The `cb7-update` package in the same distribution is unrelated PC software — a
Windows installer for the "SD-Jukebox" application, not keyboard firmware.)
