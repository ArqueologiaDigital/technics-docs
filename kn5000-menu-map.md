# KN5000 Menu Map (main CPU, program v10)

Every screen the KN5000 firmware can show, how you reach it from the panel, and where EXIT takes
you. This page is a browsable summary. The full map, with the widget tree of every screen, is the
generated file [`docs/gui/kn5000-menu-map.md`](https://github.com/ArqueologiaDigital/technics-roms-disasm/blob/main/docs/gui/kn5000-menu-map.md) in
technics-roms-disasm (about 200 KB, 3,861 lines). The numbers below are that file's, generated from
program v10 on 2026-10-29.

**Since 2026-11-06 the generated file reads further** (lane kn5000-notes, disassembly
`notes/kn5000-notes-2026-11-06/README.md`): 158 of the 211 titles have a path (53 without, 81
before), with 275 code transitions (93 before) and 3,259 widget records. The sound editor's pages
(`TITLE_SE*`) are DirmdEmulator screens, and their method tables and switch handlers are now
modelled; `SeMenu_SendEvent`, the sound editor's title opener, is now traced. This summary has not
been regenerated from it yet: its tables and lists below are still those of 2026-10-29.

## Terms

- A **title** (`TITLE_*`, id `0x01A0xxxx`) is a screen. `RegTitle` binds each title to a view
  object, the root widget of its screen. The firmware's own name for it is the `TT_*` string.
- A **mode** (`MD_*`, id `0x0180xxxx`) has a home title. Eleven of the 21 modes are entered from a panel
  button; the rest are entered by code, through `UI_ChangeModeByIndex`.
- A **menu entry** is an `AcTitleMenu` widget whose `title` field names the title it opens.
  A screen's `exit` field says where EXIT goes.
- A step **"(by \<function\>)"** is code that opens the title: a title's procedure, or the function
  of an `AcTtlJgBox` menu box (the `*TtlJgFunc` boxes of the DISK MENU, for example), which passes
  the title's `TT_*` index to `UI_ChangeTitleByIndex` / `UI_InterruptTitleByIndex` or posts
  `EVT_CHANGE_TITLE` itself.
- A title's **path** is the shortest chain of menu entries and code steps from a mode's home title.

## How the map is made

The map is generated by
[`scripts/generators/gen_naka_menu_map.py`](https://github.com/ArqueologiaDigital/technics-roms-disasm/blob/main/scripts/generators/gen_naka_menu_map.py) from the C
sources of `v10/maincpu/ui_widgets/` and the `RegTitle` / `RegMode` registrations, read through
the parser and GUI graph of
[`scripts/analysis/naka_gui_model.py`](https://github.com/ArqueologiaDigital/technics-roms-disasm/blob/main/scripts/analysis/naka_gui_model.py). The code steps come
from the function opens_by_routine() of
[`scripts/converters/name_title_index_operands.py`](https://github.com/ArqueologiaDigital/technics-roms-disasm/blob/main/scripts/converters/name_title_index_operands.py),
which walks each routine's control flow back from every call of the three index routines and names the
operand (`ldw wa, TT_DKLD`). `make menu-map` regenerates the file, and `make gui-check`, part of
`make gate`, fails when it is stale.

The panel buttons come from the mode-key maps `PanelButton_ModeKeyCodes*` in
`ui_widgets/naka_extension_device.c`, one `MD_*` byte per button. `PanelButton_ModeKey`
(`audio/audio_control_engine.s`) maps the lowest set button bit through them and posts
`EVT_SW_IN_MODE`, which `boot/main_title_ctrl_panel.s` turns into `NAKA_MODE_MD_PS + payload`.
`PanelButton_ModeKey_FilterTarget` can redirect two sequencer keys: EASY REC opens `MD_SEQ` when
byte 0x26FC is 1, and MENU opens `MD_SEQ_PLAY` when bit 0 of 0x266A is set. The button names are the
MAME driver's `CPL_SEGn` / `CPR_SEGn` port names.

## Reading a screen in the source

Each title's screen record in the C sources starts with a generated header that repeats its row of
the map. From `v10/maincpu/ui_widgets/naka_disk_menu_file_io.c`, cut short:

```c
    /* ==== SCREEN TITLE_DKMENU "DISK MENU" -- "TT_DKMENU", title id 0x60, function NAKA_APFUNC_DefaultFunction ====
     * Path: mode MD_DISK
     * Menu: "STYLE CONVERT" -> TITLE_STYLCNVWAIT
     * Menu: "HARD DISK MAIN MENU" -> TITLE_HDDEXT
     * Menu: "LOAD" -> by code, NAKA_MAINFUNC_LoadTtlJgFunc
     * EXIT -> TITLE_PS */
    .DiskMenu = {
        .class_ = NAKA_CLASS(TtlScreen),
        .super = NAKA_NONE,
        .sub = OBJ_StyleConvert_AcTitleMenu,
        .flag = VF_Fixed | VF_Const,
        .rect = NAKA_XYWH(0, 0, 320, 240),
        .color = CL_Gray,
        .border = BD_Single2,
        .exit = TITLE_PS,
        .window = RAM_DiskMenu_Window,
        .title = SELF(DiskMenu_text),
        .icon = idICON_i147,
    },
```

The "HARD DISK MAIN MENU" entry, `Cheap_HardDiskMenuView`, is one of the 28 records registered at
DRAM addresses; the map reads them through the two `Boot_InitWorkRAM` images. How every field of
such a record is spelled is on [UI Framework]({{ site.baseurl }}/ui-framework/#widget-records-in-the-c-sources).
